Directed forward

One next hop at a time, when the square should not hear it.

The flood is readable

A mesh flood can be read by every hop. That is the right tool for the shoutbox. It is the wrong tool when the path should stay a line.

The outer layer names one peer

A P2P_FORWARD body is the next peer, a time to live, and an inner frame. Only the next hop is named on the outside. The rest of the path is inside the wrap.

Each hop unwraps once

That hop checks that it is the named peer, peels one layer, and finds a smaller forward, or the payload. The time to live counts down. The last inner frame in the tutorial is a signed chat message, hello via onion.

Check it

examples/onion-forward.js in @fabric/core builds a two-hop path and peels it. No port is opened. The live path is Peer#sendOnion.

node examples/onion-forward.js
