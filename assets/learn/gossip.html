How peers talk

Peers on different computers, carrying signed messages for each other.

A network with no center

The public Fabric network is not a site you log into. It is programs, called peers, that speak the same protocol. Each peer remembers a few neighbors. Messages hop from neighbor to neighbor. That pattern is gossip.

You are a key

A peer is a key, not a username. When you send a public message, you sign it. Anyone can check the signature. A relay that carries the message does not become the author.

A hallway, then the square

Before gossip, two peers open a TCP connection and wrap it in NOISE. Ping and pong live in that session. Gossip starts once the session is up. The default listen port is 7777.

A signed envelope

A public message is an AMP frame: a 208-byte header, then a body. The header names the author and the message type, and it carries a double-SHA256 of the body. Peers drop a frame whose hash does not match the body, then check the BIP340 signature.

When those checks pass, the peer forwards the same bytes. It does not re-sign, and it does not rewrite the message to count the hop. Your signature still verifies after the frame has passed through strangers.

What is public

Some messages are flooded: discovery, a nickname, the shoutbox, a contract namespace, a Bitcoin block tip. The shoutbox, P2P_CHAT_MESSAGE, is cleartext. Every hop can read it. That is the public square.

Private delivery does not use that flood. It uses a directed forward, covered later in this path.

Check it

examples/fabric-basic-usage.js in @fabric/core signs one chat message, Hello, Fabric., and verifies it with the same key. A new message has a genesis parent: 32 zero bytes.

scripts/gossip-relay.js starts one peer that validates and floods. No Hub HTTP, no Bitcoin wallet, and no documents.
