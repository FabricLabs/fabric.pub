Named federations

A descriptor, a threshold, and a vault every member can derive.

Who, and how many

Several Hubs can form a federation with one shared Bitcoin vault. Nothing is signed without each operator's approval. The descriptor names the validators, the threshold, the network, and a publisher who is one of those keys. Its id is a hash of that descriptor, so the order of the validators does not change it.

Two addresses, same keys

The Hub's default internal key is nums, so vaults that already hold coins keep their address. The same keys with musig2 produce a different address. Coins on the first address stay there until someone sweeps them.

examples/federation-vault.js checks both addresses for two fresh keys and a threshold of 2, on regtest. Nothing is broadcast, and nothing is scanned.

node examples/federation-vault.js
