Sidechain and Beacon

A document with a clock, and one string for the epoch.

A document with a clock

Sidechain state is a version, a clock, and content. The digest hashes those three. The same state hashes the same. Two different states do not.

One patch

A patch is an RFC6902 list, the clock it was based on, and the digest from before the change. examples/message-bridge.js in @fabric/http sends one: add /hello with value world, at basis clock 0. The fields keep a canonical copy of that list, and the JSON view offers the same path back. There is no filesystem and no Hub in the script.

node examples/message-bridge.js

The epoch

A Beacon epoch seals that kind of state on the Hub's clock: the contracts root and the sidechain digest. Validators sign one string for the epoch. That seal is the Beacon's own record. It is not an application's CONTRACT_MESSAGE traffic.
